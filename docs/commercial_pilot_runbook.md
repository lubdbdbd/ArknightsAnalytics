
```powershell

```

备份通过 SQLite 在线备份和 `PRAGMA integrity_check` 校验；导出程序会先执行匿名化、字段范围、跨表引用和阶段门禁校验，再刷新 CSV、SQLite 视图与报告。

## 3. 内容预热与专项意向

每个渠道使用相同素材、相同观察周期和独立来源参数。两个商品方案在同一页面同时展示，避免不同样本结构造成伪差异。

建议内容结构：

1. 角色与使用场景：新约能天使角色视觉、桌面展示或随身收藏场景。
2. 方案A：亚克力制品，展示尺寸、工艺、预计价格和预售周期。
3. 方案B：吧唧（徽章），展示尺寸、工艺、预计价格和预售周期。
4. 明确说明：这是非商业学习项目的匿名意向研究，不收取费用，不构成预售。

有效意向必须同时满足：知情同意、接触IP不少于3个月、角色偏好不低于3分、购买意愿不低于4分、可接受价格不低于方案价格下限。每个已批准方案至少积累30条有效意向，按渠道观察曝光、点击、CTR、有效意向率、平均意向和价格接受度。

## 4. 供应商寻源

公开商品页面只能用于发现可能的零售或渠道线索。只有对方直接提供以下材料后，才能写入供应商报价表：

1. 可核验的授权链路或授权证明文件引用。
2. 对应商品方案的 MOQ、打样费、量产单价、阶梯价和付款条件。
3. 打样周期、量产周期、包装方式、交期承诺和延期处理。
4. 材质、尺寸、色差、瑕疵率、抽检方式和售后责任。

每个商品方案至少取得3家独立供应商的有效报价。相同供应商可以分别报价两个方案，但不能用同一供应商的多次报价凑足3家。联系话术和记录字段见 `docs/supplier_rfq_template.md`。

## 5. 阶段门禁

| 阶段 | 准入条件 | 未达标动作 |
|---|---|---|
| 候选审批 | 同一角色下2个商品方案 | 不开展对外验证 |
| 内容预热 | 产生可追踪真实曝光 | 检查链接与渠道参数 |
| 意向池 | 每个方案有效意向≥30 | 继续定向招募，不补造数据 |
| 供应商验证 | 每个方案授权核验供应商≥3 | 继续询价，不进入收款 |
| 小单试点 | 每个方案真实支付订单≥10 | 不进行扩量判断 |
| 履约 | 每个方案签收率≥90% | 暂停扩量并修复交付问题 |
| 购后复盘 | 每个方案有效评价≥5 | 继续回访，不声称完成闭环 |

订单试点必须在候选、意向、供应商三个前置门禁全部通过后进行。系统会拒绝未审批候选、少于30条有效意向、少于3家授权供应商、无已接受报价或金额不一致的支付订单。

## 6. 决策输出

- **需求验证**：比较两个方案的有效意向率、价格接受度、预售容忍度和渠道差异。
- **供应评估**：比较授权完整性、MOQ、单位成本、样品成本、交期和可接受瑕疵率。
- **试点经营**：比较支付转化、客单价、取消率、交付周期、售后率和退款金额。
- **购后体验**：比较满意度、质量评分、交付评分和复购意愿。
- **扩量条件**：需求、供应、履约和评价均通过门禁，且不存在授权或重大质量风险。
- **停止条件**：授权不可核验、投诉集中、退款异常、履约失败或数据样本不足。

## 7. 外部依赖边界

- 本机地址只能用于本机演示；真实对外投放需要部署到可访问的 HTTPS 域名或经审批的问卷平台。
- 向供应商发送消息、取得报价、收款、生产和发货属于真实外部业务动作，必须由项目负责人确认并执行。
- 未取得的意向、报价、订单和履约结果始终保持为空，不用模拟 ERP 数据替代真实商业成果。
