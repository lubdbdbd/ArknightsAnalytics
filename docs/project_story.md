# 项目叙述口径

## Business Goal

ACG 周边运营不能把单个平台的播放量直接等同于购买需求：老内容天然积累更多曝光，角色在不同社区的讨论结构也不同，单看声量容易造成热门角色过度备货、长尾角色错失需求或高客单商品库存积压。本项目建立“官方内容热度—跨平台一致性—商品适配—内容预热—意向验证—供应商—订单履约—经营复盘”的可解释分析链路，为角色选取、周边选品、预售验证和商品运营提供数据依据。

## Data Scope

- Bilibili：通过低频 related 图递归整理并校验549条官号历史视频，覆盖2019—2026年、8类内容；以30条显式干员PV为角色锚点，形成30名角色、271条上线Campaign关联，并将直接角色内容与共享活动曝光分层保存。
- Weibo：采集官方账号最近 100 条公开博文快照，按角色别名、标题和正文进行实体归因；近期窗口内有 3 名角色取得可用的角色级交叉验证。
- Xiaohongshu：由于官方开放平台暂不提供任意账号笔记读取能力，使用 4 组公开品牌生态快照衡量平台大盘环境，不将其伪装成角色级官方数据；同时提供人工导入模板，等待后续补充角色笔记样本。
- Commerce：采集首批 84 条淘宝公开商品快照，用商品 ID、价格、公开收货人数下界、搜索排名、授权标记和品类标签验证商业信号；只有明确标注官方/授权的商品进入核心销量与价格计算，同人及未标明商品只保留在质量审计中。
- Survey：完成243份匿名问卷回收，拆分出729条角色Top-3排序和1,701条七品类价格带观测；不采集个人身份信息，原始导出缺少提交时间与填写时长，因此只执行结构、重复、范围和逻辑校验。
- Skland：通过森空岛攻略站公开搜索接口，对60名候选角色分别采集热度榜与时间榜Top 20；按标题实体、单字角色与异格长名规则清洗，保留浏览、收藏、点赞、评论和来源链接，不调用文章浏览写入接口。

## Technical Approach

1. 对播放、点赞、投币、收藏、评论、转发和弹幕等指标进行发布时间归一化，构建 Reach、Momentum、Engagement、Intent 与 Discussion 五类子指标，避免老内容仅凭累计曝光长期占优。
2. 以 Bilibili 为主要角色样本、Weibo 为近期交叉验证来源，计算 Cross-platform Consistency、Confidence 与 Data Quality Grade；平台缺失时使用中性分而非零分，避免把“未观测”误判为“低热度”。
3. 通过角色别名词典和边界规则完成实体识别，并对“望”“余”等单字角色加入严格匹配，修复普通语句造成的假阳性归因。
4. 将角色热度扩展为 Evergreen、Viral Potential、Merch Opportunity 与 Commerce Validation Priority，区分长线稳定角色、短期爆发角色和需要淘宝数据进一步验证的角色。
5. 对淘宝商品构建异格名—基础名—昵称别名治理、IP 产品线隔离和定向搜索相关性门禁；使用 Demand、Supply、Visibility、Price Power 与 Assortment 构建商业信号，再与内容热度组成选品象限。
6. 依据正版货盘将商品拆分为亚克力制品、通行证、吧唧（徽章）、毛绒玩偶、手办模玩、装饰摆件和日用生活7类，分别维护参考价格、成本、直播适配和生产风险，并使用 SQLite、SQL、Excel 与 Markdown 报告输出角色榜单、平台矩阵、选品建议和风险队列。
7. 将问卷角色、品类和渠道偏好转化为需求权重，构建SKU、订单、库存、采购、售后和财务七表模拟ERP；通过订单头明细对账、库存流水平衡和固定随机种子保证数据可复核。
8. 新增真实商业试点层，以八张业务表记录候选审批、Campaign、匿名意向、供应商报价、订单、履约事件、售后和评价；通过授权证明、知情同意、金额对账、跨表引用和阶段门禁保证只有真实、完整的记录才能进入结果报告。
9. 将内容、问卷、森空岛和淘宝四类角色信号按“可用证据动态归一”融合，缺失来源不按0分处理；用内容优先、问卷优先、社区优先、商业优先和平衡五套权重计算排名区间，识别对权重不敏感的稳定角色。
10. 使用问卷七品类价格观测的P25/P50/P75形成入门、核心和高配价格梯度，只用淘宝明确官方/授权商品校准市场价；对模拟ERP建立ABC-XYZ、GMROI、28日需求、安全库存、再订货点、售后Pareto和7日滚动经营指标。

## Quantified Results

- 建立30名角色的大规模热度矩阵，处理549条Bilibili官号内容、271条角色Campaign关联、100条Weibo官方近期博文和4组Xiaohongshu品牌生态快照。
- 当前内容热度 Top 3 为新约能天使、凯尔希·思衡托、予愿安洁莉娜；其中予愿安洁莉娜、纯烬艾雅法拉和斩业星熊具备近期 Weibo 角色级交叉验证，其他角色需结合淘宝成交、收藏和评价数据继续验证。
- 淘宝首批包含 50 条新约能天使定向结果和 34 条全 IP 稳定自然结果；定向搜索相关率为 70%，相关商品公开收货人数下界合计至少 249，Top 10 结果贡献约 70.28%，证明搜索结果必须先做相关性与集中度校验。
- 全 IP 横截面中仅 5 名榜单角色获得可归因商业信号，凯尔希·思衡托、新约能天使和荒芜拉普兰德暂列前三；该结论仅代表当前公开销量页样本，不作为真实市场份额。
- 完成243份匿名问卷回收与字段审计，其中194人接触过《明日方舟》、113人购买过《明日方舟》正版周边、108人对随机商品表达较高购买意愿；18～22岁样本175人，占72.02%。角色Top-3加权偏好前三为德克萨斯、维什戴尔、史尔特尔。
- 生成210个SKU、6,000张订单、7,652条订单明细、18,900条库存日快照、355张采购单和392条售后记录，共33,719条模拟ERP业务记录；90天模拟经营口径下净销售额119.32万元、毛利率39.75%、退货率4.73%、缺货率0.08%，所有经营数字均明确标记为模拟。
- 构建70项自动化测试，覆盖采集解析、B站内容分类与Campaign归因、淘宝质量、问卷文本导入、ERP金额对账、库存、授权门禁、真实/模拟隔离、匿名采集门户、供应商线索隔离、HTTP接口和数据库导出等模块，当前代码覆盖率为82%。
- 将 SQLite 从结果存储扩展为运营计算层，建立18个业务视图、43组分析查询和29个索引，使用 JOIN、CTE、窗口函数、条件聚合与 CASE WHEN 输出角色验证、内容漏斗、供应商比价、渠道表现、订单对账、采购到货、履约、售后Pareto、库存周转、补货及滞销队列；通过 `EXPLAIN QUERY PLAN` 验证索引命中。
- 建立210个角色×品类候选组合和七阶段商业试点门禁；当前仅候选池完成，内容预热、专项意向、供应商、真实订单、履约和购后评价均保持空白并标记为 `blocked`，避免将未来目标包装成既有成果。

## Interview Version

我没有直接做一个“播放量排行榜”，而是先解决发布时间、平台互动含义和角色实体误匹配三个偏差，再把官方内容拆成 Reach、Momentum、Engagement、Intent 和 Discussion。商业层也没有直接把搜索结果数当供给量：首批淘宝定向页只有 70% 结果真正命中目标角色，我因此增加异格别名治理、IP 隔离、广告过滤和销量档位截断标记。最终把内容热度与 Demand、Supply、Visibility、Price Power、Assortment 组成二维矩阵，并为每项结论附带 Confidence。下一步通过相同商品 ID 的周期复采，才能计算真实的销量代理增速、上新率和下架率。

## Limitations

本项目结论是公开数据分析与方法演示，不代表鹰角网络、平台官方销量或真实商业结论。Weibo 近期窗口只能验证少量角色，Xiaohongshu 暂无角色级官方笔记数据；淘宝“收货人数”是公开下界代理且受个性化排序影响，模拟 ERP 不能用于声称真实 GMV。商业试点当前没有真实曝光、供应商和订单数据，正式选品还需持续复采商品快照并实际完成专项意向、授权核验、订单履约及售后复盘。
