# 商业数据决策

本模块把经营分析转为可核验的产品定义假设。输入均为既有模拟ERP，未执行真实补货、清仓或营销，不以方法演练证明真实增长。

## 输入与核对
- 210个SKU，90天、18,900条日库存快照；6,000张模拟订单及采购入库记录。
- SKU日快照唯一、日期连续、件数非负整数；期初+采购入库+可再售退回−出库=期末。
- 相邻日期期末/期初衔接，期末−锁定=可用，请求−实际出库=未满足请求。
- 采购已收货量按SKU/日期与入库量匹配；请求量与模拟已支付且已发货/签收的订单明细匹配。
- 支付商品数量8,368件，库存实际出库8,227件，未满足出库请求7件；支付数量不可替代实际出库。
- 原生成器将订单日期作为请求日期，未记录真实出库时间。固定单位成本用于库存演练，不等于财务结账。

## 指标定义
|指标|本模块口径|边界|
|---|---|---|
|窗口售出占比|出库 / (出库+期末库存)|不是生产批次售罄率；连续补货/退回会影响|
|库存周转天数|日末库存成本均值 / 窗口出库成本 × 窗口天数|毛出库、固定成本口径；不是财务退货净额|
|可售天数|期末可用库存 / 近28天日均实际出库|零出库时不可计算；不填0或无穷|
|期末库存成本|期末数量 × 单位成本|不是零售额，也不是已损失金额|
|去化风险金额|被规则标记SKU的期末库存成本|不是优化节省金额；缺少批次库龄|
|假设ROI|(扣退款收入−口径内总成本)/口径内总成本|商品、履约、赠品、平台、推广成本；不含固定成本、税费|
|假设销售额/推广费|情景GMV / 推广费|假设全部归因，不是实际ROAS或增量收益|
|LTV|暂不计算|缺用户ID、购买历史、获客成本和成熟观察窗口|

如“投入20万元、利润30万元”中的利润已扣全部成本，ROI是30/20=150%；若30万元指回款，则还需扣成本后计算。利润不能重复减同一笔成本。示例与本项目无实际交易关系。

## 规则与运营动作
配置文件 config/business_decisions.json 可修改演练阈值：
1. 供给受限：未满足请求>0且请求缺口率≥2%；核对缺货日期与到货，验证滚动补货，不能据受限销量简单下调需求。
2. 覆盖不足：可售天数小于采购交期+7天；核对在途、锁定库存后再确定补货。
3. 去化缓慢：可售天数>90且售出占比<30%；复核在途与促销成本，提出缩减首批、调整规格/价格带的小批量验证。
4. 近期无出库：近28天出库0且有可用库存；先检查上架、曝光、资料，不能直接断言商品没有需求。
5. 标签可以重叠，覆盖不足与供给受限不是同一含义。

默认数据得到48个覆盖不足、3个供给受限SKU；0个去化风险SKU。阈值没有制造积压结论。
整体售出占比62.61%、周转82.60天、期末库存成本428,591.58元。分类汇总按金额加总后计算，不平均SKU比率。

## 反向优化商品定义
每个SKU输出：现象 → 数量/时间证据 → 运营动作 → 下一轮产品假设 → 验证路径。
当前没有价格弹性或因果实验，不能凭“某商品卖得慢”直接断言“价格太高”；需排查曝光、缺货、交期、规格和质量。
已有问卷参与模拟需求生成，模拟销量不是对问卷结论的独立验证。

## 运行与展示
运行 python scripts/build_business_decisions.py。
页面 /#business，GET /api/business-decisions?download=markdown 或 json。
报告输出 reports/generated/business_decisions/report.md 与 report.json。
只读取CSV快照，不包含商品维护页未回写的覆盖值，不自动改采购/价格/订单。
ROI复用config/gmv_scenarios.json中的基准及4类策略假设。原退款快照存在异常，故不将其净利润混入此模块。

## 用户价值下一步
加入稳定脱敏用户ID，按首次购买月份建立用户组；先输出固定90/180/365天人均净收入和人均贡献、样本人数及观察完整度，再研究未来价值预测。收入LTV与贡献LTV必须分别命名，不能用客单价或满意度替代。

## 简历表述
商业数据决策：基于210个模拟SKU、18,900条日库存快照，核对订单请求、采购入库与库存流量，建立售出占比、库存周转天数及可售天数分析；识别48个库存覆盖待复核SKU和3个供给受限SKU，将经营信号转化为补货节奏、首批数量及商品规格的验证建议，并结合5组营销情景比较ROI与盈亏平衡条件。
