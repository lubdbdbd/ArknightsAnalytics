## 分析用途

1. **供给结构：**按店铺、品类统计商品档案数、规格数与可售规格数，识别供给集中的品类及待研究的空白。
2. **价格结构：**按市场、币种、品类比较最低标价、商品起售价中位数与最高标价；商品起售价中位数每个商品只计一次，避免多规格商品被重复加权。
3. **角色覆盖：**核验中英文角色名称和商品规格候选关联，再与原有问卷需求对照。名称匹配本身不代表购买意愿。
4. **上新与内容：**筛选资讯相关性后整理活动与上新线索，结合内容发布时间观察传播；单次观察不能推导因果关系。

两家海外商店当前公开价格均为 USD，币种证据单独保存。价格不含未确认的运费、税费、地区折扣，不能直接与淘宝人民币价格计算价差。available 是页面可售标志，不是库存数量或销量。商品分类是规则候选，保留原始品类供人工检查；例如“盲盒”属于售卖形式，与材质或实物品类不属于同一维度。

## 质量与范围

26 项质量检查覆盖实体去重、来源链接、规格与商品关联、规格计数核对、价格有效性、Endfield 排除和增量数量核算。新增测试验证跨店同 ID、重复规格、未知价格/状态、英文词边界、搜索标题匹配、查询分页和导出等场景。

原森空岛搜索文件含 830 个命中 ID，其中 582 个符合原来的直接标题匹配口径。本轮与这 582 个有效内容比较，不把原有未匹配内容算作新增。

B站相关推荐、微博最近帖子与森空岛 Top20 搜索均存在覆盖范围限制，不是全平台全量数据。合并档案包含不同采集时间，不能把混合时间的互动总量视为同一天的横截面。公开资讯搜索匹配不等于上新公告，需使用 relevance 字段筛选。

## 复现与访问

在项目根目录使用现有虚拟环境：

```powershell
# 不联网，从已保存的本轮快照重建 CSV、SQLite 和报告
.\.venv\Scripts\python.exe -X utf8 scripts/build_public_expansion.py --run-date 2026-09-12

# 未来日期创建新的采集批次；同日期目录已存在时停止
.\.venv\Scripts\python.exe -X utf8 scripts/collect_public_expansion.py
```

采集器对每个来源限速，失败时记录错误并停止该来源，不自动重试拒绝响应。商店币种未能验证或改变时停止该店数据入库。来源请求记录、原始批次和 SHA-256 清单分别保存在原始批次目录与报告的 summary.json。重建是对指定批次与原项目基线的比较，不会覆盖原项目的历史排名或自动累计所有后续批次。

平台重新启动后增加以下只读接口：

- `GET /api/public-expansion`：最新已生成批次的数量、字段与检查摘要。
- `GET /api/public-expansion/data/official_store_products?q=Plushie&limit=20&offset=0`：关键词筛选、分页。
- `GET /api/public-expansion/export/official_store_products?q=Plushie`：按同样筛选条件导出带 UTF-8 BOM 的 CSV，Excel 可读取。

其他数据表通过摘要的 tables 白名单查询。新增层保存在独立 SQLite 中，原首页综合排名尚未引用它；可在 API 或 SQLite 中分析，避免未经币种、相关性和样本偏差处理就混入原评分。
