# ERP核对中心与退款口径复现

## 本轮完成的工作

在“ERP数据处理”中新增“ERP核对中心”，对6张业务源表执行30项明确列出的规则：商品主档210条、订单头6000条、订单明细7652条、库存日快照18900条、采购单355条、售后记录392条。金融汇总属于下游报表，不作为这些规则的独立原始凭证。

核对重点：主键必填与唯一、必需数值非空且有效、SKU和订单关联、订单头明细金额、库存日平衡与跨日结转、可售库存、采购数量金额及日期、采购逾期、售后订单与SKU组合、按订单聚合退款与实付比较。数量按库存日、采购单、订单等各自粒度统计，不能把这些分母相加计算一个“整体通过率”。

异常清单提供记录编号、源表、CSV行号、观测值、计算依据与复核建议；支持级别/规则筛选、分页和导出全部筛选结果。CSV使用UTF-8 BOM并转义公式起始字符，Excel可直接打开。完整历史业务数据不因核对操作而改写。

## 实际发现与修正

历史模拟快照按2026-08-29期末核对，发现44笔订单存在已关闭退款超过实付的异常，另有1笔未收齐采购单已逾期，属于跟进提醒。

典型记录：ORD-0000151。商品原价699元，优惠69.90元，实付629.10元；旧模拟售后记录退款699元。根因在生成器按“原价×退款件数”计算，遗漏优惠分摊。

已将退款生成改为“明细商品净收入×退款件数÷购买件数”，换货仍为0。本模拟口径不包含运费退款；不能直接套用为真实平台的所有退款规则。

使用相同输入、90天周期、6000张订单和随机种子20260903重新生成并独立核对：

| 指标 | 历史快照 | 修正生成结果 |
| --- | ---: | ---: |
| 30项规则中的数据异常命中 | 44 | 0 |
| 采购逾期等跟进提醒 | 1 | 1 |
| 售后记录数量 | 392 | 392 |

共149条售后退款金额变化，合计差额2931.25元。部分旧退款未超过整单实付，仍存在未分摊优惠的问题，所以149条修改不等于44笔越界订单。该差额是模拟数据的口径修正，不是追回款项、成本节约或销售收益。

SKU、订单头、订单明细、库存、采购和售后非金额字段逐项验证一致，排除了更换样本或随机种子造成的指标变化。另修正了订单对账将空值、非数值及无穷值漏判的问题；非法数量也不能被分组求和掩盖。

**数据版本说明：本轮修正了生成器并完成独立重建验证；data/processed下原历史快照保留用于复现。当前看板中的净销售、退款和毛利仍来源于旧快照，不能称为已刷新后的数值。** 正式替换时需保留旧版证据，并同步重建售后、财务、渠道、SKU诊断、每日指标、SQL视图及依赖报表，不能只修改某个总额。

## 页面演示

1. 进入“ERP数据处理 → ERP核对中心”，先解释库存快照末日，避免按电脑当前日期误判历史采购逾期。
2. 选择原始快照，在退款异常中查看ORD-0000151，展示实付与累计退款、CSV源行号及复核依据。
3. 筛选“跟进提醒”，查看PO-000064，解释逾期采购需要确认剩余数量和到货日期，不能直接当作数据错误抹除。
4. 切换“异常演练”，程序仅在内存副本中修改4处：实付金额、期末库存、实收数量、售后订单号。展开“查看前后值”并按规则筛选，说明一个输入可触发多条核对规则。
5. 导出当前筛选的CSV复核清单；分页不截断导出。需要协作的事项可在已有日常运营待办中手工登记编号、问题及所需支持。

## 独立复现命令

```powershell
.\.venv\Scripts\python.exe scripts/verify_erp_refund_fix.py --output reports/generated/erp_refund_verification
.\.venv\Scripts\python.exe -m pytest tests/test_erp_checks.py tests/test_erp.py tests/test_platform_api.py
```

验证脚本输出历史异常明细、149条退款变化明细、修正前后摘要和输入文件SHA-256。它不改写原始CSV。若原始输入或样本已经变化，比较断言会失败，需要重新确认数据版本，不能继续引用本文固定数值。

API：`GET /api/erp/checks`，参数包括`scenario=snapshot|demo`、`severity=error|warning`、`rule`、`page`、`limit`、`download=true`。统计卡片覆盖全部规则，异常列表与导出按已应用筛选。空表或无有效日期不会被显示为相应规则已通过。
