# Arknights Analytics 商业试点执行规范

## 1. 项目定位

项目名称统一为 **Arknights Analytics｜《明日方舟》IP周边选品与商品运营分析平台**。

平台以公开内容、淘宝公开商品快照和243份真实匿名问卷形成选品假设，再通过内容预热、意向登记、供应商比价、小批量订单、履约、售后和复盘验证假设。项目不自行生产未经授权的IP商品，只允许现有官方或明确授权商品进入付费试点。

## 2. STAR落地结构

### S｜项目背景

角色内容热度不能直接等同于周边购买需求。运营同时面临角色与品类匹配不清、价格区间缺少证据、搜索结果混入同人或无关商品、供应商信息不可比、库存和售后风险无法提前观察等问题。

### T｜项目目标

围绕1个角色方向和2个候选正版SKU，建立“用户洞察—内容预热—意向验证—供应商评估—订单交付—售后复盘”的小批量商品运营闭环，并让每一步都具备数据来源、准入门槛和可复核结果。

### A｜核心动作

1. 使用内容热度、角色偏好、品类高意愿占比和商业代理信号生成候选池。
2. 对两个候选方向设计A/B内容，记录曝光、点击和落地页UV，不在需求验证阶段直接收款。
3. 对进入落地页的用户进行匿名意向登记，收集购买意愿、可接受价格和预售容忍期。
4. 每个候选SKU至少比较3份报价，核验授权证明、MOQ、成本、样品、生产或到货周期及售后条款。
5. 只有“候选审批通过且供应商授权证据通过”的SKU可以录入付费订单。
6. 对订单金额、付款、发货、签收、取消、退款和评价建立状态记录与SQL对账。
7. 通过CTR、意向转化率、成交转化率、取消率、履约及时率、售后率、毛利率和满意度复盘是否扩量。

### R｜结果口径

当前只报告已经验证的数据资产和试点准备度，不预填未来结果。实际执行后，系统将从真实记录计算：

- 内容：Impressions、Clicks、CTR、Landing UV。
- 意向：Qualified Intent、Intent Conversion、Accepted Price。
- 供应：Verified Quote Count、MOQ、Unit Cost、Lead Time、Supplier Score。
- 订单：Paid Orders、Paid Conversion、Cancellation Rate、AOV。
- 履约：Delivery Completion、Ship Days、Delivery Days。
- 售后：After-sales Rate、Refund Amount、Resolution Days。
- 评价：Satisfaction、Quality、Delivery、Repurchase Intent。

所有门槛都是本项目的小样本试点准入规则，不描述为行业基准。

## 3. 阶段门禁

| 阶段 | 最低门槛 | 未通过时动作 |
|---|---:|---|
| 候选池 | 至少1个可解释候选 | 补充角色或品类证据 |
| 内容预热 | 产生可追踪曝光与点击 | 修正内容与埋点 |
| 意向用户池 | 每个已批商品至少30条有效专项意向 | 不进入采购与订单 |
| 供应商验证 | 每个已批商品至少3家授权证据通过的供应商 | 继续比价，不选定供应商 |
| 订单试点 | 10至20个付费订单 | 不扩大备货 |
| 履约 | 目标完成率不低于90% | 暂停扩量并定位交付问题 |
| 复盘 | 至少5条有效购后评价 | 继续回访，不输出满意度结论 |

## 4. 数据录入

真实试点模板位于 `data/manual/commercial_pilot/`。模板禁止记录姓名、手机号、邮箱、账号、住址、物流单号或评论原文：

- 用户只保存不可逆的匿名 `lead_id`。
- 供应商只保存内部 `supplier_code`，授权材料使用脱敏文件引用。
- 订单只保存项目内部 `order_id`，不保存平台账号和收货信息。
- 评价只保存结构化分数和去标识化摘要。
- 所有真实记录必须填写 `is_simulated=false`。

执行：

```powershell
.\.venv\Scripts\python.exe scripts\build_commercial_pilot.py
```

脚本将执行数据校验，并输出候选清单、阶段门禁、SQLite视图和试点准备度报告。任何金额对账、授权状态、跨表引用或评分范围错误都会阻断更新。
