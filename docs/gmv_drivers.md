# GMV驱动分析与营销情景

## 使用

运行 `python scripts/build_gmv_drivers.py` 生成 `reports/generated/gmv/report.json` 与 `report.md`；工作台入口 `/#gmv`。GET `/api/gmv-drivers` 提供模拟订单诊断和固定预设情景，POST `/api/gmv-drivers/scenario` 对给定基准与方案即时计算，不保存或执行任何营销动作。页面输入修改后会隐藏旧结果，点击“计算当前方案”后刷新。

## 三个口径不能混用

1. 支付商品GMV＝已支付订单的商品原价金额－优惠金额；不含运费，未扣退款。取消订单不计入。
2. 支付商品GMV＝支付订单数×商品客单价。此时已包含重复购买产生的订单，不能再乘复购率或购买频次。
3. 在同周期、同人群、同来源且身份去重一致时，可写为UV×购买用户转化率×人均支付订单数×商品客单价。转化率分子是去重支付买家，不是支付订单数。复购率只是至少购买两次的人数比例，不等于人均订单数。

ERP只有客群标签，没有客户ID，也没有曝光、访客或访问事件。系统保留访问转化、购买频次和复购率为空。支付订单数÷创建订单数只能称订单支付完成率。公开社媒互动不能拼成商品去重UV。

## 订单分析流程

- 先核对头明细金额与唯一性，以订单为粒度聚合，防止一对多重复计额；商品GMV+已支付订单运费应等于含运费实付。
- 拆解最近两个完整28日经营窗口，分别计算支付订单与客单价。变化贡献为 `Δ订单×(前后客单价均值)` 与 `Δ客单价×(前后订单均值)`，交互项平均分配，两项合计等于GMV变化。零订单期间客单价未定义，不强算分解。
- 按渠道和客群标签比较订单、商品客单价、优惠、每单件数。渠道差异是描述性结果，不能证明渠道投放有效。
- 当前原始售后快照仍保留退款未分摊优惠的问题。只展示退款越界数量，不把该快照计算出的净销售和利润当作可靠经营结果；修正流程见ERP核对文档。

## 营销测算流程

`config/gmv_scenarios.json` 提供独立演练基准和4类方案：组合销售、阶梯优惠、限量溢价、大促节点。UV、转化、频次、成本及效果变化均为明确假设，不是由ERP或问卷推算的真实效果。

- 潜在订单＝假设访客×购买用户转化率×购买频次。
- 预计支付订单＝潜在订单与假设承接订单上限的较小值；上限按订单而不是库存件数计，不替代SKU库存核对。
- 优惠后客单价＝优惠前购物篮金额×(1－优惠比例)。这里使用代表性购物篮，阶梯优惠只测算选定档位，不模拟全量购物篮分布、优惠叠加或用户需求弹性。
- 预计GMV＝预计支付订单×优惠后客单价。
- 贡献利润＝GMV－假设退款－商品成本－履约成本－赠品成本－平台费－推广投入。平台费假设按退款前GMV计费、退款后不返还；退货不回冲成本。这些规则可与真实业务不同，未含固定成本与税费，不是净利润。
- 在单订单贡献大于0时计算覆盖推广投入的最低订单数，以及达到基准贡献利润所需的订单数，同时检查访客与承接容量是否可行。
- 固定预设4种方案×3档购买用户转化假设（80%/100%/120%），形成12组敏感性情景。它们不是随机试验，更不能写成“转化率提升20%”。

## 从假设转向真实验证

建立统一记录：实验编号、方案及版本、起止日期、合格用户条件、稳定分组、渠道、商品、页面曝光/访问、匿名用户ID、支付订单、优惠、营销费用、履约与退款。匿名标识应使用合规获得的业务ID，不采集公开买家个人资料。

实验启动前确定主指标、成本与退款护栏、需要的样本量及最小可检测差异；按用户稳定随机分组，避免同一个用户重复进入不同组。没有随机条件时，报告观察差异并披露季节、渠道及商品构成变化，不能包装成因果提升。

具体方案：套装与单品对比；优惠档位和赠品成本比较；有授权和真实供给约束的限量价格验证；大促同期对照。以支付转化、贡献利润、取消、退款和履约作为联合判断依据。

## 简历口径

基于6,000张模拟订单，按支付订单数与商品客单价拆解GMV，对连续两个28日窗口进行变化贡献分析；构建组合销售、阶梯优惠、限量溢价及大促4类营销方案，开展12组转化假设敏感性测算，联动折扣、成本、退款及承接容量评估成交与贡献利润，输出实验方案和数据补采要求。

禁止将模拟GMV、情景增幅、待执行实验写成真实销售或增长业绩。
